Entangled observations and irregular time

01 看到的是整体，背后却可能有多套动态

一段视频包含多个运动部位，一组轨迹包含多个相互作用的物体。序列模型拿到的往往只有混在一起的特征，既不知道应该如何划分，也不能假定观测等间隔到来。

  1. 输入：带时间戳的整体观测特征之间没有预先提供的实体划分，采样间隔可以不均匀。
  2. 学习：模块动态与相互作用寻找有用的潜在分工，并跟踪模块之间如何交换信息。
  3. 输出：任务所需的预测未来轨迹、物理连接或视频类别，由对应任务的读出头给出。

混杂，指的是缺少划分先验

三体实验每个时刻输入一个 9 维位置向量，但不把“哪三个维度属于哪个天体”的分组交给模型。视频则先变成特征，再交给序列模型处理。“混杂”不要求特征在每个时刻重新打乱。

不规则，指的是时间间隔不固定

只在部分时刻获得观测时，模型需要利用实际时间戳，而不是把所有相邻观测都当成相同长度的一步。连续时间模型为这种情形提供自然的表示。

核心问题

能否同时学习“有哪些潜在模块”“每个模块如何变化”和“模块之间如何交互”，让复杂序列的学习具有更明确的结构？

Decoupling-based Neural System

02 把子系统的状态与交互的状态分别建模

DNS 的解耦发生在潜在特征空间：多个子系统各自接收控制信号、维护隐藏状态；另一个元系统维护它们之间随时间变化的交互权重。

整体观测c(tk)

多个可学习映射 pi，生成不同的控制信号

子系统 1x1(t) → z1(t)
子系统 2x2(t) → z2(t)
子系统 nxn(t) → zn(t)
交互元系统A(t)

读取潜在状态，更新交互；交互权重参与子系统的状态更新

潜在状态 → 任务读出 → 轨迹预测 / 连接预测 / 动作识别

第一层分工：不同控制，不同状态

\[x_i(t_k)=p_i\!\left(c(t_k)\right),\qquad z(t)=[z_1(t),\ldots,z_n(t)].\]

每个 \(p_i\) 都从同一份观测中学习不同的特征组合，为第 \(i\) 个子系统产生控制信号 \(x_i\)。子系统数量 \(n\) 是模型超参数，不需要等于真实物体的数量。

第二层分工：状态如何变，信息如何流

\(z_i(t)\) 描述潜在模块的状态；\(A(t)\) 描述这些模块之间的信息混合方式。它们共同演化，交互没有被压缩为一个固定矩阵。

这里的“相对独立”是一种建模偏好。子系统仍通过 \(A(t)\) 耦合；实际实现还共享更新状态的向量场网络，以不同的控制信号形成分工，减少参数开销。

解耦的目标是有用的潜在分工

模型没有被要求把每个子系统固定为一个天体、一颗小球或一条手臂。这样的对应关系是否出现，需要通过分析来检验。

From discrete observations to continuous evolution

03 用受控微分方程连接观测与模块动态

DNS 先把各子系统的离散控制信号插值成连续路径，再用路径的变化驱动隐藏状态。交互矩阵决定每个子系统在更新时读取哪些潜在状态。

子系统：控制路径驱动状态变化

\[\mathrm{d}z_i(t)=F\!\left([A(t)z(t)]_i\right)\,\mathrm{d}x_i(t).\]

\([A(t)z(t)]_i\) 是第 \(i\) 个子系统接收到的加权状态，\(F\) 把它映射为向量场，再与控制路径的变化 \(\mathrm{d}x_i(t)\) 相乘。所有子系统共享 \(F\)，各自使用不同的 \(x_i\) 与 \(z_i\)。

在观测时间戳上得到 \(x_i(t_k)\) 后，三次样条插值提供中间时刻的控制和导数。对可微控制路径，积分形式为：

\[z_i(t_1)=z_i(t_0)+\int_{t_0}^{t_1}F\!\left([A(s)z(s)]_i\right)x_i'(s)\,\mathrm{d}s.\]

这样，数值求解器沿连续时间推进，不要求相邻观测具有相同时间间隔。面对噪声，还可以将控制路径的三次样条插值替换为自然平滑样条；这一变体记为 DNSS。

元系统：交互始终满足约束

DNS 将交互矩阵限制在逐行的概率单纯形上：

\[\mathcal S=\{A\in\mathbb R^{n\times n}:A\mathbf 1=\mathbf 1,\ A_{ij}\geq0\}.\]

每行非负、总和为 1。因此 \([Az]_i=\sum_j A_{ij}z_j\) 可以解释为第 \(i\) 个子系统对潜在状态的加权读取，自身状态也包含在可选信息中。

投影微分方程（ProjDE）为受约束的动态提供一个建模视角：

\[\dot A=\Pi_{\mathcal S}\!\left(A,g(A,z)\right).\]

对于欧氏投影 \(P_{\mathcal S}\)，方向算子写为：

\[\Pi_{\mathcal S}(A,H)=\lim_{\alpha\to0^+}\frac{P_{\mathcal S}(A+\alpha H)-A}{\alpha}.\]

它描述沿候选方向变化、同时受可行域约束的行为。有限步数值计算需要相应的投影或约束参数化；下一章区分两种具体选择。

soft 版本实际怎样更新交互？

DNS 的 soft 版本通过 logits 矩阵 \(L\) 表示交互，并使用 query / key 得分的时间变化：

\[A(t)=\operatorname{softmax}_{\mathrm{row}}(L(t)),\qquad R(z)=\frac{Q(z)K(z)^\top}{\sqrt{d_k}}.\]
\[L(0)=R(z(0)),\qquad \dot L(t)=\frac{\mathrm{d}}{\mathrm{d}t}R(z(t)).\]

\(d_k\) 是 key 的维度。计算采用 Euler 离散，同时推进潜在状态与交互状态；soft 版本在更新 \(L\) 后逐行归一化得到 \(A\)。连续情况下，二者通过链式法则联系：

\[\dot A=J_{\operatorname{softmax}}(L)\,\dot L.\]

这个关系说明 logits 的变化怎样传递到交互权重。它依赖这里的 softmax 参数化和得分动态，不能推广为任意交互方程都具有相同的演化轨迹。

Two interaction preferences on the simplex

04 平滑分配信息，还是允许连接精确归零？

同样满足非负与归一化，softmax 和 sparsemax 却产生不同的交互结构。前者保留平滑、稠密的权重，后者允许一部分潜在连接变成零。

DNS：softmax

\[a_j=\frac{\exp(\ell_j)}{\sum_k\exp(\ell_k)}.\]

有限 logits 对应严格正的权重，适合连续地调整信息分配。它可从熵正则化的优化视角理解，是平滑归一化；对概率向量再应用 softmax，通常仍会改变该向量。

DNSG：sparsemax

\[a=\underset{p\in\Delta}{\arg\min}\ \tfrac12\|p-\ell\|_2^2.\]

\(\Delta=\{p:p\geq0,\sum_jp_j=1\}\)。这是严格的欧氏投影，已经位于单纯形中的向量保持不变；输出可以包含精确的零，也可能仍然稠密。

为什么这种投影适合神经网络？

sparsemax 具有阈值形式的闭式解：

\[a_j=\max(\ell_j-\tau,0),\qquad \sum_j\max(\ell_j-\tau,0)=1.\]

阈值 \(\tau\) 保证归一化。激活集合不变时，梯度也有闭式表达；激活集合切换的位置需要按分段可微映射处理。因而它既能施加明确的几何约束，也便于放入可训练的计算图。

Bregman 散度提供什么视角？

“距离”可以由一个凸函数 \(\phi\) 定义，而不必总是使用欧氏距离：

\[D_\phi(p,q)=\phi(p)-\phi(q)-\langle\nabla\phi(q),p-q\rangle.\]

平方范数对应欧氏几何；负熵对应与 KL 散度相关的几何。这个视角把不同归一化、正则化与投影选择联系起来，帮助讨论交互结构的偏好。它不意味着 softmax 是 logits 空间中的欧氏投影，也不意味着已证明某种选择必然训练更快。

05 交互在变化，模块的分工也可以出人意料

三体与弹簧案例分别展示了两件事：元系统会随轨迹变化调整交互，不同投影还会形成不同的潜在连接模式。

The method's value and scope

07 用显式结构，降低学习复杂动态的负担

DNS 的核心是两类状态的分工：子系统描述潜在模块的演化，元系统描述模块之间的交互。连续控制路径连接不规则观测，单纯形约束组织信息流。

贯穿整个项目的设计

从整体观测学习多条控制路径，用共享向量场推进不同子系统，再让随时间变化的交互矩阵调节它们的信息交换。soft 与 sparse 两种选择，将平滑性和稀疏性带入这一动态过程。

  • 潜在解耦与物理发现之间仍有距离。三体案例得到的是特征分工；交互权重也不等于物理力、真实邻接或因果关系。
  • 模块数量需要选择。最佳数量未必等于物体数量，实验通过超参数搜索确定，方法没有自动识别唯一的真实分解。
  • 连续模型仍需数值近似。控制路径的插值或平滑方式、Euler 步长及噪声条件都会影响实际行为。
  • 实验结论有明确范围。三个基准支持这套结构在所测任务上的价值；它们不证明对所有复杂系统都最优，也没有保证物理守恒或长时间预测稳定性。

这项工作提供了一条可复用的思路：当整体序列难以直接建模时，可以把模块动态与交互动态分别表达，再通过任务结果和结构分析共同检验这种分解是否有效。
