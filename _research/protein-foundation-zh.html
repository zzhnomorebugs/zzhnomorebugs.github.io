Protein generation at scale

01 让千万级 MSA 数据真正支撑生成模型训练

这项上海人工智能实验室的工作，以多序列比对（MSA）为条件训练蛋白质序列生成模型。核心工程任务是把三千多万条序列对应的数据处理、存储、供给与模型实验接成一条可运行的训练链路。

一百余 GB最终预处理产物

朴素方案初始估算为十余 TB；通过统计表示与存储类型调整，形成紧凑的 HDF5 数据。

约 40%tokenizer 环节提速

多种处理方式计时比较后，相较默认方式提升该预处理环节的速度。

150M / 650M两种规模完成训练

先用 150M 模型开展短程配置对照，最终两种规模各完成一版训练。

贯穿项目的工程思路：把可复用的工作移到训练之前

记录位置只索引一次，MSA 统计离线完成，训练时再恢复 profile。模型侧先做短程对照，再投入完整训练，让数据准备与模型迭代各自有清楚的边界。

From MSA conditions to sequence generation

02 模型如何利用 MSA，生成新的蛋白质序列？

MSA 将相关序列对齐。沿同一列统计氨基酸频率，得到 profile，告诉模型“这个位点在已有序列中常见哪些类别”。生成模型结合这一条件、当前状态与时间信息，逐步提出候选序列。

模型设计：围绕骨干、条件与采样开展对照

模型侧将 ESM-2 Transformer 改造为扩散 Transformer（DiT），并在共享的 650M 架构上比较贝叶斯流网络（BFN）与离散流匹配（DFM）。MSA 条件的使用方式也是研究对象，包括加性 profile 嵌入、Perceiver 交叉注意力，以及 DFM 的 profile 初始化策略。

数据接口：profile 是怎样得到的？

以下用四条示意序列解释模型所需的统计量。第二个位点中 C、T 各出现两次，因此两类频率均为 0.5。

\[C_{j,a}=\sum_{m=1}^{N}\mathbf{1}[x^{(m)}_j=a],\qquad P_{j,a}=\frac{C_{j,a}}{N}.\]

\(N\) 为参与统计的序列条数，\(j\) 为位点，\(a\) 为类别；序列长度为 \(L\)，类别数为 \(K\)，因此计数与 profile 均为 \(L\times K\) 数组。profile 仅记录逐位点频率，不能独自表达位点间的协同关系；生成仍依赖模型的序列上下文。训练需要的是 \(P\)，离线保存 \(C,N\) 就足以在加载时恢复它。这一接口决定了后面的存储设计。

Index once, process in parallel

03 数据处理：减少重复查找，分摊统计计算

profile 的计算本身很直接，规模放大后，重复定位、解析和 token 转换都会累积成开销。数据链路按“先定位，再计算”的顺序拆分优化。

瓶颈 1 · 重复查找

建立“记录标识 → 存储位置”索引

每次提取目标 MSA 都从头扫描，会反复访问无关记录。先扫描建立位置索引，之后按目标标识直接定位，再读取与解析，复用已有的查找结果。

瓶颈 2 · 统计任务量大

按目标分块，交给多个 CPU 节点

各目标的 MSA 统计可以分别进行。把记录分成若干块，让多台 CPU 服务器承担定位、解析、tokenize 与按列计数，形成训练可读取的预处理产物。

瓶颈 3 · token 转换反复执行

用计时对照选择 tokenizer 处理方式

对多种实现分别计时比较，选择效率更高的方式。相较默认处理方式，tokenizer 环节提速约 40%；这一数字对应局部预处理环节。

单个目标的离线处理 · 伪代码

position = record_index[target_id]
msa_record = read_record_at(position)
aligned_tokens = tokenize(msa_record)
counts, msa_count = aggregate_by_position(aligned_tokens)

位置索引解决“读哪里”，分块并行解决“谁来算”，tokenizer 对照减少单条记录的转换开销。完成计算后，还要解决另一个规模问题：这些统计量应当以什么形式长期保存？

Store counts, normalize on load

04 存储设计：保存整数计数，使用时恢复频率

既然模型使用的 profile 可以由计数和分母恢复，就可以让磁盘保存紧凑的 \(C,N\)，把浮点归一化留到训练加载时。这把模型需要的统计信息与长期存储形式分开。

第一层：聚合 MSA 深度

沿 \(N\) 条序列统计，将逻辑上的 \(N\times L\times K\) 类别指示量汇总为 \(L\times K\) 计数。模型使用逐位点 profile 时，无需持久化完整 one-hot 展开。

第二层：选择紧凑整数表示

计数天然是整数。在相同 \(L\times K\) 形状下，以能覆盖计数范围的紧凑整数类型存储，减少每个元素所占的字节数；读取时再转成浮点数。

离线保存与训练加载 · 伪代码

# 离线：保存整数计数及分母
save_h5(integer_counts=C, msa_count=N)

# 训练：读取后恢复模型需要的频率
C, N = load_h5(record_id)
profile = to_float(C) / N

这里保留的是精确计数。整数位宽需要覆盖最大计数，类别表与对齐处理规则也必须前后一致。上述容量变化来自表示方式与存储类型的共同调整：前者为初始估算，后者为实际产物规模。

对训练的意义

解析、token 转换和按列计数都在离线阶段完成。训练侧读取计数并归一化即可使用 profile，避免每次访问样本都重复计算同一统计量。

From controlled runs to full training

05 训练落地：先筛选配置，再投入完整训练

数据准备完成后，训练还需要同时解决两件事：用对照实验筛选模型实现，并检查数据读取是否能持续供给计算。先用 150M 模型开展短程实验，再推进两种规模的完整训练。

训练侧：比较时间条件如何进入网络

时间变量描述当前噪声阶段，time embedding 把它编码后注入网络。固定其余训练设置，替换时间条件的注入实现，在相同步数下观察 loss 与收敛趋势，辅助选择训练配置。

\[e_t=\operatorname{TimeEmbed}(t),\qquad \widehat{x}=f_\theta(x_t,e_t,P).\]

上式概括当前生成状态 \(x_t\)、时间条件 \(e_t\) 与 MSA profile \(P\) 三类输入。loss 对照限定在相同训练目标与定义下。

供数侧：检查并发设置，而不只增加 worker

训练过程中曾遇到 worker 数较大时出错、读取效率下降，以及 GPU 利用率无法充分提升的问题。因此，存储容量和运行时供数要分别考察：离线产物减少重复计算，并发读取仍需结合实际运行表现调整。

数据访问、CPU 处理和模型计算共同决定训练进度。最终完成 150M、650M 两种规模的训练，是这条数据与模型链路的落地结果。

生成侧：采样算法另做对照

模型训练之后，还需选择怎样迭代生成序列。采样研究比较 BFN 的 Langevin、ODE、SDE 方法，以及采样步数与起始时间等设置。训练 loss 回答配置是否在学习，生成阶段的评估则用于考察候选表现。

项目使用 pLDDT、pTM 与共进化接触质量等结构代理指标评估候选。这些指标提供结构层面的预测证据，功能与真实实验效果仍需进一步验证。

Engineering contributions

06 将模型设计接到可运行的大规模训练链路

模型设计确定如何利用 MSA 条件，工程实现则让这些条件能够被大规模地计算、保存和送入训练。项目重点在于把两者连接起来，并用前期对照支持完整训练。
