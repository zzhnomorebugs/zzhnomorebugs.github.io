Protein generation at scale

01 让大规模序列数据成为可训练的生成条件

项目希望训练能够生成蛋白质序列的模型，为后续的候选筛选与目标性质研究提供基础。实习工作的重点是把生成方法落实到可运行的训练流程，并解决大规模数据的预处理、存储和供给问题。

  1. 输入：蛋白质序列与 MSA从多序列比对中提取逐位点的氨基酸分布，为生成提供条件。
  2. 训练：学习序列生成规律先做短程对照，再确定模块与配置，投入完整训练。
  3. 输出：待筛选的候选序列通过后续评估与筛选，研究具有目标性质的序列。

这项工作在上海人工智能实验室开展。面对三千多万条序列，仅把算法接入模型还不够：如果每次查找 MSA 都重复扫描原始数据，或把中间表示全部展开保存，预处理与存储本身就会成为训练的限制。

数据工程

建立记录位置索引，组织多服务器分块处理，对比 tokenizer 处理方式，并将 MSA profile 改为紧凑的整数计数存储。

训练与实验

实现和比较时间条件的注入方式，开展采样算法与超参数对照，在前期 150M 实验的基础上完成 150M、650M 两种规模的最终训练。

From aligned sequences to a profile

02 把多条对齐序列，汇总成每个位点的频率

MSA（Multiple Sequence Alignment，多序列比对）把相关序列放到共同的对齐位置上。沿同一列统计氨基酸类别，就能得到这个位点在输入 MSA 中的变化与保守程度。

设参与统计的 MSA 有 \(N\) 条序列，长度为 \(L\)，类别数为 \(K\)。将每个位点的类别转为 one-hot，沿序列条数这一维相加，再除以 \(N\)：

\[C_{j,a}=\sum_{m=1}^{N}\mathbf{1}\!\left[x^{(m)}_j=a\right],\qquad P_{j,a}=\frac{C_{j,a}}{N}.\]

\(C\in\mathbb{N}_0^{L\times K}\) 保存整数计数，\(P\in[0,1]^{L\times K}\) 是 profile。类别表及对齐处理规则需要在预处理和训练读取时保持一致。

示例中，第一个位点的 A 频率为 1，表示这几条输入序列在该位点完全保守；第二个位点的 C、T 各占一半，生成时仍需要结合条件与序列上下文作出选择。profile 提供的是逐位点频率，不能独自表达不同位点之间的协同关系，也不把生成结果硬性限定为逐列复制。

Index once, process in parallel

03 先知道数据在哪里，再并行计算 profile

大规模预处理的第一步是减少重复查找。为目标蛋白质找到对应的 MSA，不应每次都从原始数据的第一条记录开始逐条匹配。

位置索引：把查找与解析分开

预处理先建立“记录标识 → 存储位置”的索引。处理某个目标时，先查到对应位置，再读取并解析该记录的 MSA。这样，扫描原始数据的工作可以在建立索引时完成，后续按目标提取时复用定位结果。

位置索引的数据流 · 伪代码

position = record_index[target_id]
msa_record = read_record_at(position)
aligned_tokens = tokenize(msa_record)
counts, msa_count = aggregate_by_position(aligned_tokens)

这里的 position 是记录位置的抽象表示；关键是避免重复从头扫描。索引负责定位，解析和 tokenizer 负责把取出的记录转为可统计的序列，两者分别优化。

分块处理：把独立目标分配给多个 CPU 节点

将目标记录分成若干块，在多台 CPU 服务器上同时处理。每个任务负责定位、读取、解析与 profile 计数，使庞大的语料可以并行完成预处理，再形成训练可读取的 HDF5 产物。

tokenizer：用计时对比选择处理方式

定位提速之后，序列解析和 token 转换仍会被重复执行数千万次。因此，对多种 tokenizer 处理方式分别计时、列表比较，选择效率更高的实现。最终相较默认处理方式，获得了约 40% 的提速，这一结果对应预处理中的 tokenizer 环节。

Store counts, normalize on load

04 保存整数计数，把频率计算留到加载时

profile 的分子本来就是整数。既然频率可以由计数与 MSA 条数恢复，就不必把每个位点、每个类别的频率长期保存为浮点数。

  1. 统计：MSA → C 与 N沿 MSA 深度方向累加 one-hot，得到逐位点类别计数。
  2. 落盘：HDF5 整数表示保存紧凑整数计数，并保留恢复频率所需的 MSA 条数。
  3. 加载：C / N → profile转为浮点并归一化，交给模型作为生成条件。

存储与加载的数据流 · 伪代码

# 离线预处理：C 的形状为 [L, K]
C = sum(one_hot(msa_tokens), axis="msa_depth")
save_h5(integer_counts=C, msa_count=N)

# 训练加载：只在使用时恢复频率
C, N = load_h5(record_id)
profile = to_float(C) / N

这里保存的是精确计数，而不是把小数概率截断成整数。只要整数类型的范围能够覆盖最大计数，读取后的 \(C/N\) 就能恢复对应的经验频率。位宽因此应由 MSA 深度与计数范围决定。

表 1 · MSA、整数计数与浮点 profile 的表示区别
表示逻辑形状保留的信息在流程中的用途
对齐后的 MSA token\(N\times L\)每条序列各个位点的类别离线统计的输入
one-hot 展开\(N\times L\times K\)逐条序列的类别指示量解释聚合运算的中间表示

聚合去掉了 MSA 深度这一维；在相同的 \(L\times K\) 形状下，紧凑整数表示又减少了每个元素所占的字节数。这是两层不同的空间优化：前者改变保存的统计表示，后者改变统计量的存储类型。

Compare before the full training run

05 用短程实验筛选模块，再投入完整训练

训练一版较大的生成模型需要较多资源。前期先用 150M 模型运行短程实验，在其余训练设置一致的条件下，对比相同步数下的 loss，再确定后续使用的模块与配置。

训练侧：比较 time embedding 如何进入网络

时间变量描述当前的噪声阶段，time embedding 将这一信息编码后注入网络。即使骨干与训练目标相同，时间条件进入网络的方式也会影响模型学习去噪的过程，因此将它作为可替换模块进行对照。

\[e_t=\operatorname{TimeEmbed}(t),\qquad \widehat{x}=f_\theta(x_t,e_t,P).\]

上式概括模型接收的三类信息：当前状态 \(x_t\)、时间条件 \(e_t\) 和 MSA profile \(P\)。实验改变时间条件的注入实现，其余设置保持一致，在同一步数上观察 loss 与收敛趋势。比较限于相同训练目标与 loss 定义下的配置。

采样侧：算法与超参数单独对照

训练完成后，还需要通过迭代更新生成序列。因此，另行比较 diffusion 采样算法及其超参数，研究生成过程中的更新方式与控制选项。训练 loss 用于判断训练配置，采样算法的表现则需要在生成阶段考察。

表 2 · 实验分工：训练配置筛选与采样研究
对照方向实际比较的内容判断依据与作用

供数效率：更多 worker 不等于更高吞吐

训练中还遇到过数据加载 worker 数较大时出错、读取效率下降，以及 GPU 利用率无法充分提升的问题。这说明数据已能放入磁盘，并不代表它能持续跟上模型的计算速度；读取并发也需要结合实际供数效率来调整。

数据访问、CPU 处理和模型计算共同决定训练进度。预处理阶段把解析、token 转换与 profile 计数提前完成，让训练可以直接读取计数并归一化，减少反复计算同一统计量的工作。

  1. 150M：短程对照在相同训练设置下比较候选模块的收敛表现。
  2. 确定模块与数据流程结合配置对照与数据处理优化，形成完整训练方案。
  3. 150M + 650M：最终训练完成两种参数规模的模型各一版训练。

Engineering contributions

06 把数据处理与实验流程，接到最终模型训练

这项工作的主要贡献集中在生成模型的工程实现：使大规模 MSA 能够被定位、统计、紧凑保存并送入训练，再通过充分的前期对照减少完整训练中的反复试错。

一百余 GB最终预处理产物

朴素方案的初始容量估算为十余 TB；以整数计数及分母保存 profile 所需信息。

约 40%tokenizer 环节提速

对多种处理方式计时比较，相较默认处理方式提升预处理效率。

150M / 650M最终训练规模

前期使用 150M 做短程配置对照，最终两种规模各完成一版训练。

贯穿其中的做法是：把反复查找改为位置索引，把独立统计分给多个 CPU 节点，把可恢复的浮点频率改为整数计数存储，再将训练与采样的不同选择放到各自的对照流程中。由此，大规模数据处理与模型实验形成一条能够实际运行的链路，为后续候选生成与性质筛选提供基础。
