Property-driven protein design

01 Given a target property, generate sequences worth testing

Protein engineering seeks amino acid sequences with a desired function. Controllable generation gives the target property directly to the generative model, providing a clear direction for proposing candidates.

  1. Input: Reference sequence and target propertyThe reference sequence provides sequence context; the target condition describes the desired property.
  2. Generation: Stepwise conditional updatesGradually adjust amino acid class predictions under the constraints of a sequence prior.
  3. Output: Candidate variantsScreen candidates through independent evaluation for subsequent experimental validation.

A generative model must meet two requirements: the sequence itself should be plausible, and the generated result should respond to the target condition. When proposing variants relative to a reference sequence, the extent of the edits also needs attention, so that pursuing the target property does not disrupt the original sequence and structure.

The project's central question

Can a general protein sequence prior provide a reusable foundation for different property tasks, with conditional adaptation producing candidates that move toward the desired target?

What does the target condition express?

A condition can describe a variant effect, a change in stability, or a binding property. The model learns the relationship between the target condition and sequence changes, while each task retains its own label definitions and evaluation methods.

What does the output mean?

The output consists of candidate sequences that require further validation. Predicted properties, confidence in predicted structures, and actual experimental effects provide distinct levels of evidence.

Dividing the work between a general prior and task conditions

02 Learn sequence patterns first, then learn target conditions

Natural protein sequences provide broad statistical patterns, a reference sequence supplies conditions for relative editing, and property labels specify the task's direction. These sources of information work together to generate candidates.

Training a conditional generator directly requires learning both sequence patterns and the influence of property conditions. This project separates those responsibilities and gives each type of data a distinct role: unconditional generative pretraining uses public natural protein sequence collections to learn general sequence patterns; downstream training then freezes the prior and trains only the conditional guidance, or residual model, on a smaller task dataset with property labels. Unconditional pretraining does not require a downstream property label for every sequence; those labels teach the task-specific correction. The workflow has three stages:

  1. Pretraining: Learn sequence patternsLearn to predict clean tokens from noisy states using a large protein sequence collection, producing a reusable general generative prior.
  2. Conditional training: Learn to correct predictionsFreeze the prior and train the conditional residual on a smaller task dataset with property labels, using the loss on the combined prediction.
  3. Conditional generation: Predict and update repeatedlyKeep both models fixed and progressively update the generation state under the given conditions to obtain candidate sequences.

For editing tasks conditioned on a reference sequence, the objective can be expressed as learning a conditional distribution:

\[p_\theta(x\mid x_{\mathrm{ref}},y).\]

Here, \(x_{\mathrm{ref}}\) is the reference sequence, \(y\) is the target property, and \(x\) is a candidate sequence. This notation expresses the task objective; it does not imply that the model guarantees every candidate will satisfy the condition.

From conditional score decomposition to residual prediction

03 Break conditional generation into prior prediction, residual correction, and state updates

Each generation step first asks which amino acid may occupy each position, then adjusts those predictions for the target condition. The following steps explain what the two models read, how their outputs combine, how the residual is learned, and how the prediction enters the generation loop.

The motivation: Conditional score = unconditional score + conditional correction

For a continuous noisy variable \(x_t\), taking the logarithm of Bayes' rule and differentiating with respect to \(x_t\) gives the following decomposition of the conditional score. Here, \(y\) denotes the condition to illustrate the decomposition:

\[\underbrace{s_{\mathrm{c}}}_{\text{conditional score}} =\underbrace{s_{\mathrm{u}}}_{\text{unconditional score}} +\underbrace{\nabla_{x_t}\log p_t(y\mid x_t)}_{\text{conditional correction}}.\]

In the model design, this decomposition motivates adding the prediction outputs of two networks, while learning the prior from large sequence datasets and the guidance from smaller task datasets. The first term comes from a general-prior network, which undergoes unconditional generative pretraining on public natural protein sequence collections and whose parameters are frozen during downstream training. The second comes from a conditional-residual network trained only on a smaller task dataset with property labels. It uses the current state, reference sequence, and target property to learn the required correction. The loss acts on the combined prediction and updates only the second, residual network. The first network still contributes a prediction at every step, but its weights remain unchanged.

This division of work draws on the conditional-control intuition behind CFG. The continuous score decomposition above supplies the design motivation; the quantities actually added in this project are the discrete token logits output by the two networks. The logit residual is not identified with a continuous score or a classifier gradient.

3.1 Read the same state, with different responsibilities

Let \(s_t\) denote the current generation state at time \(t\). For BFN, it is the class-probability belief at each position; for DFM, it is a noisy sequence of discrete tokens. The state \(s_t\) is what changes during generation, while the reference sequence \(x_{\mathrm{ref}}\) and target property \(y\) provide the conditions for this run.

General prior: Supply the base prediction

It reads \(s_t\) and time \(t\), then outputs \(\ell_{\mathrm{prior}}\): base scores for each amino acid class at each position, given the current information. Its weights remain fixed during downstream training to reuse the sequence patterns learned in pretraining.

Conditional residual: Supply the correction

It reads the same \(s_t,t\), together with \(x_{\mathrm{ref}},y\), then outputs \(r_\phi\): a score correction for each position and class. The reference sequence provides context for relative editing, while the target property specifies the desired direction.

3.2 Add the logits, then obtain clean-token probabilities

Logits are class scores before normalization. For a sequence of length \(L\) with \(K\) classes, each branch outputs an \(L\times K\) score table. Add matching elements, then apply softmax over the classes at each position:

\[\begin{aligned} \ell_{\mathrm{cond}}&=\operatorname{stopgrad}\!\left(\ell_{\mathrm{prior}}(s_t,t)\right) +r_\phi(s_t,t,x_{\mathrm{ref}},y),\\ q_i(k)&=\operatorname{softmax}(\ell_{\mathrm{cond},i})_k. \end{aligned}\]

Here, \(i\) denotes a position and \(k\) an amino acid class. The probability \(q_i(k)\) predicts the clean token at that position; the generation rule must still use it to determine the next state update. Normalizing at each position does not discard relationships between positions: both branches use the sequence context.

What does the residual actually correct?

Consider abstract classes \(\alpha,\beta\). The prior may favor \(\alpha\), while the current condition calls for a greater relative preference for \(\beta\). The residual can increase the score of \(\beta\) relative to the other classes, and softmax renormalizes the corrected scores. A zero residual recovers the general prior's prediction. The residual itself is neither a probability nor an instruction for an already selected mutation.

3.3 Train the combined prediction, updating only the residual

Once the prior has been pretrained, downstream training updates only the conditional residual. It uses a smaller task dataset of real sequences with reference context and property labels, focusing the learning signal on the correction needed for the target condition. One training step can be understood as follows:

  1. Construct the training input. Use the real sequence \(x\) as the clean target, sample a time \(t\), and construct its noisy state \(s_t\) according to the chosen framework. Supply the reference sequence and the property condition associated with that training example.
  2. Compute both outputs. The frozen prior supplies base logits, and the residual model supplies a correction based on the state and conditions. Combine them into the prediction \(q\), as shown in Figure 2.
  3. Supervise the combined result with the real sequence. Use the generative training objective of the corresponding BFN / DFM framework to learn to recover clean sequences. The specific losses differ between frameworks, but in both cases conditional adaptation acts through the combined prediction.
  4. Update only the residual parameters \(\phi\). The operation \(\operatorname{stopgrad}\) prevents the downstream loss from updating weights through the prior branch. The residual learns from whether adding its correction improves the overall prediction.

Training therefore needs no separate label for a “correct residual”: the combined prediction's objective teaches the conditional correction. The property condition tells the model what kind of sequence to recover, while the effectiveness of property control must be evaluated separately on generated candidates.

3.4 Keep the models fixed and repeat prediction and state updates

Generation receives a reference sequence and a desired property, with no real target sequence to recover. Both models keep their weights fixed and propose candidates through a loop: initialize → predict with both branches → combine the distribution → update the state.

  1. Initialize the generation state. The starting state depends on the chosen path. For the base paths introduced in the next section, BFN starts with uniform class-probability beliefs, DFM-abs starts with masked tokens, and DFM-uni starts with uniformly random tokens. The reference sequence provides conditions for relative editing and should be distinguished from the current generation state.
  2. Predict, correct, and update. Recompute both logit outputs from the current \(s_t,t\) and combine them into \(q\). BFN uses it to construct messages and update probability beliefs; DFM uses it to construct transition rates and update discrete tokens.
  3. Continue until a candidate is obtained. Feed the new state back to both models so that the conditions continue to influence predictions throughout generation. Evaluate the resulting sequences independently for property response, editing behavior, and structural plausibility.
The weights stay fixed; the predictions change at every step

Both the prior and residual recompute their predictions as the state and time change; the residual is not added only once at the start. The next section expands the state-update part of Figure 2: how the same clean-token prediction drives BFN's probability beliefs and DFM's discrete transitions.

From diffusion to discrete sequence generation

04 Understand probability beliefs and discrete jumps through gradual denoising

BFN: Accumulate class information through Bayesian updates

The state \(\boldsymbol\theta\) is a probability belief over \(K\) amino acid classes, initialized to a uniform distribution. The network reads these probabilities and predicts a clean-token distribution \(q\).

\[m\sim\mathcal{N}\!\left(a(K e_x-\mathbf{1}),\,aK I\right).\]
\[\theta'_k=\frac{\theta_k\exp(m_k)}{\sum_j\theta_j\exp(m_j)}.\]

\(e_x\) is the token's one-hot encoding, and \(a>0\) controls the information added in this step. Training constructs a noisy message \(m\) from the true token. During generation, a predicted token is sampled from \(q\), a message is constructed, and the belief is updated. The update follows Bayes' rule, and the network continues to use the full sequence context at the next step.

Rather than directly updating a noisy token, BFN updates continuously valued class probabilities.

DFM: Update discrete tokens using transition rates

DFM-abs starts from an entirely masked sequence; DFM-uni starts from uniformly random tokens. Taking the linear masking path of DFM-abs as an example, \(t\) runs from 0 to 1, and an individual position gradually changes from mask \(M\) to clean token \(x\):

\[p_t(z\mid x)=(1-t)\delta_M(z)+t\delta_x(z).\]
\[R_t(M\!\to\!k)=\frac{q(k\mid\boldsymbol{x}_t,t)}{1-t},\qquad t<1.\]

\(\delta\) denotes a distribution concentrated on the specified token, \(k\) is an amino acid class, and \(q\) predicts the clean token. Over a small interval \(\Delta t\), a masked position jumps to \(k\) with probability approximately \(R_t\Delta t\). In the base generation process without a corrector, positions that have been revealed remain unchanged.

DFM constructs discrete transitions from the clean-token posterior, moving the probability distribution along the chosen path from noise toward a sequence.

The residual changes the prediction; the generative framework determines the update

Both can use \(q=\operatorname{softmax}(\ell_{\mathrm{prior}}+r_\phi)\) as the clean-token prediction. BFN uses it to generate messages and update beliefs; DFM uses it to construct transition rates. The conditional residual in Section 3 therefore retains the same division of work.

A general prior for sequence generation

05 Check that the base model is learning before training the conditional residual

The residual approach depends on the base generator supplying a usable prior. Pretraining first learns generative patterns in natural protein sequences; the downstream stage then freezes the prior and trains a correction for the property condition.

Both approaches show periods of declining loss: BFN still fluctuates later in training, while masking-path DFM continues to improve more gradually. These histories support exploring downstream methods, but do not establish that the base models are fully trained.

Using such a prior for residual prediction lets the task network draw on learned sequence patterns, while also exposing it to limits in the prior's coverage. Further analysis needs to distinguish whether weaknesses in conditional control arise from the base generation capability, residual capacity, or the training data and evaluation protocol.

Evaluate loss reduction and property control separately

Pretraining loss assesses how well the base model learns the generative objective; downstream experiments assess whether candidates approach the target property. Improvement in the former cannot substitute for the latter, nor establish that new sequences have the desired function in real experiments.

Experimental design · Property control and evaluation

06 Which property tasks benefit from the residual approach?

The experiments address three questions: how to reuse a generative prior, whether outputs respond to target properties, and which generated results the evaluation can cover. Adaptation approaches are compared within BFN and masking-path DFM separately, with property responses and editing behavior used to interpret the results.

6.3 From generated candidates to property evaluation

Error measures distance from the target, while rank correlation tests whether the target ordering is preserved. Evaluation coverage indicates how much of the generated output those metrics represent. Low error must be interpreted alongside coverage, and structural similarity cannot substitute for property control. ProteinGYM evaluation still relies on a predictor; predictions on generated sequences do not constitute new experimental validation.

6.6 Editing behavior and the limits of thermal-stability evaluation

The BFN baseline on the binding-property task frequently falls back to the reference sequence. High sequence identity may therefore indicate a lack of editing rather than better conditional control. Too few results can be evaluated to use this baseline for a meaningful relative-gain calculation. Zero-edit, single-edit, and multi-edit behavior must be checked together.

Thermal stability uses stricter experimental lookup: candidates must match the reference length, contain exactly one substitution, and uniquely match an existing experimental record in the test split. Current coverage is insufficient to rank the approaches reliably, while multi-edit candidates lack measured labels for the full combination. The available evidence therefore does not yet support a claim of improved thermal-stability control.

Method recap

07 Explicitly separate the sequence prior and conditional correction to improve property control

The residual approach explicitly separates the sequence prior from the conditional correction and improves variant-effect control over the corresponding baselines. DFM’s improvement is more pronounced on the binding-property task.

Understand the division of work through score decomposition

\[s_{\mathrm{c}}=s_{\mathrm{u}}+\nabla_{x_t}\log p_t(y\mid x_t).\]

The unconditional term supplies the language of protein sequences, while the conditional term supplies the direction toward the target property. One model learns which sequences are more plausible; the other learns how to follow the target condition.

Implement this intuition with a residual for discrete sequences

\[\ell_{\mathrm{cond}}=\operatorname{stopgrad}(\ell_{\mathrm{prior}})+r_\phi.\]

The base model learns sequence patterns in advance and remains frozen; the residual model focuses on learning the conditional correction. Together, they predict amino acids at each step, letting BFN and DFM reuse the learned sequence language for targeted generation.
